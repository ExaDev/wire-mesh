# spec/

`protocol.cddl` is generated by concatenating the authored source files below, in this order, and must never be hand-edited directly — edit a source file and regenerate.

```
identity.cddl handshake.cddl tokens.cddl transport.cddl discovery.cddl management.cddl streaming.cddl exec.cddl data-domain.cddl federation.cddl frame.cddl
```

Regenerate with:

```
cat identity.cddl handshake.cddl tokens.cddl transport.cddl discovery.cddl management.cddl streaming.cddl exec.cddl data-domain.cddl federation.cddl frame.cddl > protocol.cddl
```

No CDDL toolchain resolves multi-file imports (RFC 8610 defines no include statement), so this concatenation is the actual mechanism, not a placeholder for one. Two sockets (`$frame-variant`, `$manage-command-params`) are the deliberate extension seams later files (or a downstream project's own schema, such as Cascade's own excluded `core/content` domain) plug into without editing the core files. Ordinary rule names must stay globally unique across every file — no tool catches a collision before the concatenated file is parsed, so each file's rules share a prefix matching its own filename.

`registry/` holds the append-only core domain and capability name lists referenced from `handshake.cddl` and `tokens.cddl`.
